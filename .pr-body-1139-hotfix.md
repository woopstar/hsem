## Summary

6.3.x backport of #1142. The reporter in #1120 is on 6.3.7.

After you turn on **EV Planned Load** (or OCPP) in the options flow, its switches, target-SoC number, deadline time and sensors now appear straight away. Before this, they stayed unavailable until you reloaded HSEM by hand. The platform gates (#859) and the options listener are the same on `v6.3.0-hotfix` as on `main`, so the fix is the same.

Branch: `fix/1139-reload-on-entity-gating-change-hotfix`, based on `v6.3.0-hotfix`. It is a cherry-pick of the `main` commit.

## What changed

- `custom_components/hsem/__init__.py`
  - New `ENTITY_GATING_CONFIG_KEYS` lists `hsem_ev_planned_load_enabled`, `hsem_ev_second_planned_load_enabled`, `hsem_ocpp_enabled` and `hsem_ocpp_second_enabled`.
  - A snapshot of those values is stored on `HSEMRuntimeData.entity_gating` at setup.
  - `async_update_options` calls `hass.config_entries.async_schedule_reload()` only when one of the four flags changed. Every other options write keeps the in-place `coordinator.async_options_updated()`, including the ones HSEM's own switches, numbers, times and selectors make on each toggle.
- Registry entries of a feature that was turned off are kept as unavailable, not removed.

## Difference from the `main` PR

`tests/test_init_options_reload.py::test_setup_entry_snapshots_gating_flags` does not patch `async_migrate_devices`. That function does not exist on this branch, because the #875 device-split migration is `main`-only. There are no other differences.

## Tests

- New `tests/test_init_options_reload.py` (22 tests):
  - each gating flag, on→off and off→on, schedules a reload with no in-place refresh;
  - entity-driven options writes cause no reload;
  - unrelated options refresh in place;
  - writing a flag's default value explicitly is not a change;
  - no double reload;
  - no action after unload;
  - the setup snapshot is stored.
- `tests/test_init_setup_order.py` has been updated for the new snapshot field.
